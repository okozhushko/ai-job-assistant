# ai-career-assistant

Telegram-бот, що шукає вакансії за твоїми критеріями (посада, стек, країни) через публічні API job-бордів і показує список нових вакансій у чаті.

## Як це працює

1. `/settings` — майстер налаштувань: посада → стек → слова-виключення → країни (🇺🇦 🇵🇱 🇪🇸) → джерела. `/mysettings` показує поточні налаштування.
2. `/search` — пошук вакансій зараз за поточними налаштуваннями (до 15 вакансій за раз; повторний `/search` покаже наступні).
3. Фоновий планувальник (`SEARCH_INTERVAL_CRON`, за замовчуванням раз на 6 годин) сам шукає нові вакансії для всіх користувачів і надсилає їх у чат. `/pause` і `/resume` вимикають і вмикають його для себе.
4. Бот запам'ятовує, які вакансії вже показав користувачу, і не дублює їх. `/clear` очищає цю історію.
5. Під кожною вакансією — кнопки «Подав» (позначка зберігається й не скидається через `/clear`), «Пропустити» і «Блок компанії» (приховує всі вакансії цієї компанії).
6. Пошук іде лише за назвою посади; стек підіймає вище вакансії, де він згадується. Вакансії старші 45 днів і ті, що містять слова-виключення, відсіюються.
7. `/language` — мова бота (українська / English); за замовчуванням визначається з мови клієнта Telegram.

## Джерела вакансій (MVP)

Для MVP підключені лише джерела з офіційним публічним API:

| Джерело | Країни     | Примітка                                                           |
| ------- | ---------- | ------------------------------------------------------------------ |
| Jooble  | UA, PL, ES | Безкоштовний API-ключ на https://jooble.org/api/about              |
| Adzuna  | PL, ES     | Adzuna не покриває Україну. Ключі на https://developer.adzuna.com/ |

**Indeed** свідомо не додано в MVP: публічну Publisher API-програму Indeed закрив для нових розробників ще у 2021 році, тож стабільної офіційної інтеграції зараз немає.

**Jooble і країни:** фільтрація за країною йде через параметр `location` у тілі запиту (значення типу `Ukraine`, `Poland`, `Spain`), а не через піддомен виду `ua.jooble.org` — країнові піддомени повертають `403` для звичайного API-ключа, доступ дозволено лише на загальному `jooble.org`.

### Заплановані джерела (не в MVP)

DOU Jobs, Djinni, Work.ua, Robota.ua, Jobs.ua — Україна; No Fluff Jobs, Just Join IT, Pracuj.pl, Bulldogjob, the:protocol, RocketJobs, Inhire, GoWork — Польща; InfoJobs, Tecnoempleo, Infoempleo, Jobandtalent, Domestika Jobs, Wellfound — Іспанія.

Жоден з них не має офіційного публічного API — інтеграція вимагатиме web-scraping конкретної розмітки сайту (крихко, може порушувати ToS сайту, потребує окремої юридичної/технічної оцінки для кожного джерела перед додаванням). Кожне джерело реалізується як окремий адаптер, що реалізує інтерфейс `JobSource` (`src/sources/types.ts`), тож додавання нового джерела не змінює решту бота.

**LinkedIn навмисно виключений** — автоматизований парсинг чи дії на LinkedIn прямо порушують його Terms of Service і можуть призвести до блокування акаунта.

## Розсилка резюме (Roadmap, Phase 2 — не реалізовано)

MVP не надсилає нічого автоматично: бот лише показує список знайдених вакансій, відправку робиш сам.

Заплановане Phase 2: бот готує чернетку листа під вакансію, показує її в Telegram із кнопкою «Надіслати», і після твого підтвердження надсилає лист через твою поштову скриньку (SMTP, власні креденшли) — без масової автоматичної розсилки, кожен лист підтверджується вручну.

## Налаштування проєкту

```bash
cp .env.example .env
# заповни TELEGRAM_BOT_TOKEN (від @BotFather), JOOBLE_API_KEY, ADZUNA_APP_ID/ADZUNA_APP_KEY

npm install
npm run dev      # розробка (tsx watch)
npm run build    # компіляція в dist/
npm start        # запуск скомпільованого бота
npm run typecheck
npm run lint       # ESLint
npm run format     # Prettier --write
```

## Запуск у Docker

```bash
cp .env.example .env
# заповни .env

docker compose up --build -d
docker compose logs -f
docker compose down
```

Образ — multi-stage build (`node:24-alpine`): окремі стадії для встановлення залежностей, компіляції TypeScript і рантайму без dev-залежностей, процес у контейнері виконується від непривілейованого користувача `node`. Дані (`data/`) монтуються як volume і переживають перестворення контейнера. `HEALTHCHECK` смикає локальний `/health` ендпоінт (`HEALTH_PORT`, за замовчуванням `3000`) — бот сам по собі не має HTTP API, цей сервер піднято лише для health-перевірки.

## Структура проєкту

```
src/
  bot/            Telegram-бот: обробники команд, клавіатури, стан майстра налаштувань
  config/         Валідація змінних оточення (zod)
  domain/         Типи домену + сервіс пошуку (агрегує джерела, дедублікує)
  health/         HTTP-сервер для Docker HEALTHCHECK
  scheduler/      Періодичний фоновий пошук (node-cron)
  settings/       Зберігання налаштувань користувача (SQLite)
  sources/        Адаптери джерел вакансій (jooble.ts, adzuna.ts) + реєстр
  storage/        SQLite (node:sqlite) + трекінг "уже показаних" вакансій + одноразова міграція з JSON
data/             bot.sqlite (не в git); *.json.migrated — бекап старого файлового сховища
Dockerfile        Multi-stage build (deps → build → runtime), non-root user
docker-compose.yml
```

Дані користувачів зберігаються в SQLite (`data/bot.sqlite`, вбудований `node:sqlite`, Node ≥22.5). При першому запуску старі `settings.json`/`seen-vacancies.json`, якщо вони є, автоматично переносяться в SQLite і перейменовуються в `*.json.migrated`. Стан майстра `/settings` (проміжні кроки) живе в пам'яті процесу й скидається при рестарті.
